# Agent notes

- The active infrastructure is OpenTofu in `tofu/`, with one OCI ARM VM and a K3d cluster inside Docker on that VM. `tofu/compute.tf` renders the root `cloud-init.yaml` via `templatefile()`; change both when adding template variables. Escape literal shell `${...}` in that template as `$${...}`.
- Follow the tracked `README.md`, `deploy.sh`, and `tofu/` over local `CLAUDE.md` or `.github/copilot-instructions.md`: those older instructions refer to removed `terraform/`, Ansible, Helm/code-server files, and automatic tfvars generation. There is no application deployment script here.
- Copy `terraform.tfvars.example` to `tofu/terraform.tfvars` and supply OCI credentials and SSH public-key path. `deploy.sh` changes into `tofu/` and only supports `deploy` (default: `tofu init` then `tofu apply`) or `destroy`. Root-level state, tfvars, and provider cache are not used by it; these files and lockfiles are gitignored. Preview with `tofu -chdir=tofu plan` after initialization; get the SSH command with `tofu -chdir=tofu output -raw ssh`.
- Focused checks from repo root: `tofu fmt -check -recursive tofu`; `tofu -chdir=tofu init -backend=false` then `tofu -chdir=tofu validate`; `shellcheck --severity=warning deploy.sh`. CI also scans with Trivy, but its `tofu init` and `tofu validate` currently run at repo root rather than `tofu/`. There is no test suite.
- Keep `tofu/network.tf` ingress rules aligned with the K3d host ports in `cloud-init.yaml` (currently 8080:80, 8443:443, 6443:6443; OCI ingress currently omits 8443). `tofu apply` does not wait for cloud-init to finish: on the VM check `sudo journalctl -u cloud-final`, `k3d cluster list`, and `kubectl get nodes`. The ingress-controller readiness wait in cloud-init tolerates failure.
